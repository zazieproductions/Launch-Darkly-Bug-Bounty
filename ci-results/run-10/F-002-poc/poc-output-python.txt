secondary vector — kind 'a:b:c': error = 'context kind contains disallowed characters'
  (kind names are validated, so the exploitable asymmetry is the un-escaped *key* of a
   'user'-kind context; keys are free-form strings and are not validated for colons)

the escaping rule as implemented (context.py):
  _escape_key_for_fully_qualified_key: key.replace('%', '%25').replace(':', '%3A')
  single kind: full_key = key if kind == DEFAULT_KIND else '%s:%s' % (kind, escape(key))
  multi kind : ':'.join(kind + ':' + escape(key) for each kind, sorted by kind)
  -> escape() is skipped exactly when kind == 'user', while multi-context keys ARE escaped.
     Any user key of the form "<kind1>:<key1>:<kind2>:<key2>" therefore impersonates a
     multi-context (and vice versa) for every consumer of fully_qualified_key: secure-mode
     HMAC, event/context deduplication and cache keys.
